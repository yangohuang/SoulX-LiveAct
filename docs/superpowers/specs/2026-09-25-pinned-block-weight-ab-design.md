# Pinned block weights: quality-preserving 4090 transfer experiment

The Vivix-aligned question is whether the already implemented `--pin_block_memory` option improves LiveAct's *three-step* streaming throughput on one RTX 4090 without altering generated video or exhausting the 62-GiB host. Prior profiles at 224×384 attributed 1.196 s of the first DiT forward to 2,280 weight copies, versus 0.361 s of FP8 linears and 0.030 s of SageAttention. At 416×720 the recorded weight copies were about 1.24 s per forward. These nested profiler ranges motivate a test, but they do not predict a guaranteed wall-time gain.

## Paired low-resolution development experiment

Use image 1, exact first five seconds of `examples/audio/1.wav` (`/tmp/liveact-local-5s.wav`), seed 42, prompt `一个人在说话`, 224×384/24 FPS, three denoising steps, FP8 GEMM/KV, CPU cache and block offload, one resident KV step, cached T5/FP8, CPU T5 and no compile or latent anchor. Run a fresh pageable baseline and a fresh pinned arm sequentially in the same checkout; only the latter adds `--pin_block_memory`. Preflight GPU idle and host `MemAvailable` ≥40 GiB. Capture all block times, 1-second host-available and GPU-process-memory samples, startup time, and decoded video/audio metadata. A monitor may terminate a pinned run if host `MemAvailable` falls below 8 GiB for consecutive samples, to avoid the known 64-GiB host-memory pressure.

Evaluate later-block median (blocks 1–3), not cold-start time. Promote to the full-resolution check only if pinned is **≥15% faster** than the fresh pageable median, sampled minimum `MemAvailable` stays **≥8 GiB**, it completes and decodes normally, and the decoded videos have the same frame count. Since pinning is intended to be a storage/transfer policy, also compare decoded frames (exact per-frame hash or report MAE/PSNR if nondeterministic) and check for no new visible defect. If the result is within ±5%, rerun both arms once to exclude launch noise; between 5% and 15%, report a small/inconclusive gain and stop rather than promote. If the pinned arm fails or violates headroom, stop and record the failure, not a speed claim.

If promoted, run a fresh paired 416×720/5-second check under the same gate, changing only output resolution and documenting the memory risk. This is an inference transfer optimization study, not a new generative method; it cannot establish 24-FPS real time or long-horizon stability. Archive exact request/config, logs, sampled resources, playable videos and results. Sync only the personal fork; do not open an official SoulX PR without user review.
