# LiveAct audio lookahead and repeated-period phase audit

The exact-feature 90-second study found no preregistered long-history degradation, and the request-end audit identified final-block audio clamping plus H.264 lookahead as endpoint confounders. This read-only follow-up quantifies the **data availability implied by the existing generation code** and the alignment of a repeated feature period with its 32-output-frame block cadence. It does not modify generation, run another GPU job or infer a learned receptive field from index ranges.

Use `generate.py`'s `blksz_lst=[6,8]`, `frame_num=53`, 24 FPS, 32 later-block output frames, `audio_start_idx` and `get_audio_emb`'s ±2 lookup. Calculate for each block the first/last decoded output frame, first/last audio-feature index selected before clamping, whether the end of a finite request clamps, and the latest source-audio time a caller would need to supply before the code can form that block's condition. Audit both 30-second (720-frame) and 90-second (2160-frame) requests, and a proposed 32-second period (768 frames) repeated to 96 seconds. Confirm index predictions against the existing 10/20 diagnostic audit.

For a 30-second period, compute period-start phase modulo the 32-frame stride (0, 16, 0) and block windows spanning its boundaries. For a 32-second period, all starts should be phase-aligned. State explicitly that this removes one **experimental grouping** mismatch; it does not make generated history, noise trajectory or every block's cache state identical. Existing 90-second SyncNet trends are below threshold and cannot be attributed to phase or history from this audit.

Use the already measured 90-second later-block median time and frame count to compare audio-availability lead with compute time. Distinguish implementation lookahead (audio bytes required by the current block implementation) from true interactive latency, which also depends on when audio arrives, scheduling, encode/mux, playback and model compute. Produce JSON/report and a proposed gate for any future block-aligned long run: only spend GPU after a replicated failure case; use an exact canonical 32-second feature period, freeze source/media/seed, exclude at least the final block near each period endpoint for strict control and retain raw pre-encoder audits and a fresh-history arm.
