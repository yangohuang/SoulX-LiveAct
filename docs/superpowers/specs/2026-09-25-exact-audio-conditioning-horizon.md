# Exact model-audio-condition repetition for a 90-second causal rollout

The [prior repeated-speech study](../../benchmarks/2026-09-25-repeat-speech-history-test.md) repeated the same 30-second PCM three times but found Wav2Vec condition cosine only 0.943/0.950 between periods after whole-WAV SoX tempo and encoding. Its late–early SyncNet change was below the prespecified 0.5 signal threshold, so it did **not** establish long-history degradation. This is a new, user-prioritized long-form control experiment, not a retroactive reinterpretation of that negative result. Its aim is to compare late and early output when the **actual DiT audio tensor** repeats exactly in the interior of each 30-second period.

## Intervention and alternatives

Add default-off `--audio_embedding_repeat_source PATH` to `generate.py`. It is valid only with non-streaming audio. For each request, retain the normal target-WAV SoX/Wav2Vec path to determine the target embedding length, separately encode the supplied 30-second source WAV through the same SoX/Wav2Vec code, require a positive integer repeat count, and tile the source `[T,12,768]` embedding to the target length. The output MP4 still muxes the original request WAV. A sidecar JSON by the output MP4 records source/target WAV hashes, source/target embedding shape, repeat count, per-period raw-feature SHA-256, and SHA-256 of each interior feature span including the ±2 frames used by `get_audio_emb`. Never persist biometric or full audio feature tensors. Use `--disable_cudnn_benchmark` in both experimental runs. Exclude two seconds from each period edge in the strict condition-matching interpretation; the global endpoints of `get_audio_emb` clamp rather than wrap.

Alternatives: repeating raw PCM still leaves SoX/Wav2Vec differences; re-encoding each chunk changes the conditioning pipeline and adds boundary effects; training-time forcing is outside the one-card inference scope. Tiling one canonical feature period changes the minimum factor needed to control DiT audio while leaving model weights, denoising schedule and generated-history path intact.

## Frozen inputs and gate

Use the archived exact image-2 reference and 30-second PCM source (SHA-256 `85372c99f11ca8396d9c01bb1aa1314bb165e93000938ba87f8ad06de104637e`) and its bitwise 3×90-second PCM WAV (SHA-256 `2df37c1e0e5c4ee22c1cd6cc2839fb23b08954f5bc1a58a86e6c70216b2454b0`). Image 2, prompt `一个人在说话`, seed 43, 416×720/24 FPS, three steps, FP8 GEMM/KV, CPU block/cache offload, `resident_kv_steps=1`, no compile/pin/anchor, offline FP8/T5 caches and disabled cuDNN benchmark match within the new pair. Generate both a 90-second repeated-audio continuous rollout and an independent 30-second fresh-history control under this exact source-feature policy. The earlier 90-second video remains historical context, not a matched-condition arm.

Before long generation, test shape/hash behavior on synthetic tensors and run a short real 4090 smoke that writes a sidecar and decodes a complete video. Reject the long run if feature period hashes or interior-context hashes differ, or if the run cannot fit safely on the card. For the 90-second video verify 2162 decoded frames, 90-second audio, 68 block costs and sampled GPU/host memory. Its three 30-second SyncNet segments must have at least 90% of 750 audio-supported windows, stable best offset, and the same model/crop policy. Repeat the old screen: both full and 2-second-edge-trimmed late-minus-early SyncNet confidence must fall by at least **0.5**, and the fresh-history score must be within **0.3** of the early segment, before calling the pattern a *candidate time/history signal*. Also check boundary peak ratio ≤1.25, local motion retention ≥90%, single-face coverage ≥90%, reference-face late decline ≤0.05, mouth-motion proxy and worst-window video review. Failure of any check means no long-history degradation claim and no seed-44 run. If every screen passes, plan a separate seed-44 replication before causal attribution; exact audio matching still does not hold the noise trajectory, pose or hidden state fixed across periods.

This experiment does not train Self-Forcing/SRF, demonstrate infinite video, or imply real-time 24 FPS on one 4090. Archive feature-fingerprint sidecars, playable video, timing, SyncNet matrix, motion/face/mouth JSON and visual strips. Sync only the personal fork; no official SoulX PR without user review.
