# Frame-500 hand artifact: final-step anchor, not VAE history alone

## Question and fixed protocol

The [velocity-anchor ablation](2026-09-25-velocity-aware-anchor-ablation.md) produced white/dark hand trails around frames 501–507, while the [pre-output scalar study](2026-09-25-pre-output-boundary-signal-study.md) found no artifact-specific risk score. This [predeclared source-attribution study](../superpowers/specs/2026-09-25-hand-artifact-source-attribution.md) asks where the known failure enters the output. It is a targeted experiment on identity 2, seed 43, generated block 16 (frame 501 onward); it is not a new quality method or long-horizon success claim.

The baseline and velocity arms used the same public image 2, the first 30 seconds of audio 2, prompt `一个人在说话`, 416×720, 24 FPS, three denoising steps, FP8 GEMM/KV, block/cache offload and one resident KV step on the same RTX 4090. The image SHA-256 is `7f9c1d2567ca391200b1a76b2e07442111d4472493411b59195f80872d078550`; the audio trim SHA-256 is `85372c99f11ca8396d9c01bb1aa1314bb165e93000938ba87f8ad06de104637e`. Both generated videos decode to 722 frames. `--boundary_probe_block 16` captured the previous five and current eight clean latents in each arm. One new opt-in snapshot in [`generate.py`](../../generate.py) records the *entire* final-step predicted current block **before** `anchor_chunk_start`; the existing final snapshot records it after the correction. Default generation has no new capture. For the velocity arm, [`cross_decode_boundary.py`](../../cross_decode_boundary.py) reuses the same checkpoint VAE and exact later-block layout: prior-last-three + current-eight, discard the first nine decoded frames. The baseline probe MP4 is byte-identical to the previously archived [seed-43 unanchored diagnostic video](artifacts/videos/image2-boundary-signal-seed43-30s.mp4), SHA-256 `aee2cdc9df1ec732c99be5e2b845c48f98d1aa484b1c16ac3c9d5404b08563b7`. ## Replay gate and within-trajectory intervention

Before interpreting a counterfactual, same-arm VAE replays had to match output frames 501–508 to mean RGB MAE ≤8/255 and visual inspection. They passed at **2.569/255** for baseline and **2.655/255** for velocity; the first four rows of the full sheet confirm the correspondence. The same-arm replay therefore supports comparisons between the two velocity snapshots. The final-step anchor changes **only the first two current latents** (RMSE 0.2526, MAE 0.1401); the remaining six are byte-equal, and the prior history is byte-equal. In the hand-focused sheet, the post-anchor row has bright white hands followed by a dark transparent trail, while the **same history with the pre-anchor current block** gives a coherent hand movement without that conspicuous smear.

| Velocity history + velocity post-anchor current | 7.840 | 11.679 | 56.648 | 2.261 s |
| **Same velocity history + pre-final-anchor current** | **5.456** | 11.532 | 62.137 | 2.264 s |
| Baseline history + velocity post-anchor current | 8.175 | 11.784 | 57.217 | 2.264 s |
| Velocity history + baseline current | 6.192 | 15.600 | 86.558 | 2.264 s |

The local seam above is VAE frame 8→9 *within a single re-decode*, whereas the source MP4's immediate seam is frame 500→501 across two separately decoded blocks. They are not the same pixel pair. On the source MP4s, the 180×104 grayscale immediate seam is 4.154 for baseline versus **6.401** for velocity; the eight-transition peak is **14.707** versus 10.747, again showing why a smaller maximum frame change can coexist with worse hand quality. The warm VAE replay cost is about 2.26 seconds for a 32-frame block after the first 3.62-second call; this is a diagnostic re-decode, not a controlled end-to-end inference acceleration benchmark. It adds no DiT pass to the captured generation; running such a replay online would add nontrivial VAE latency.

The two cross-history rows are a secondary sensitivity test. White/dark hand trails remain when the velocity *current block* is decoded with baseline history, while baseline current latents remain visually clean with velocity history. This supports the conclusion that the current clean latents, rather than the VAE context alone, carry the artifact in this window. **Cross-swapping breaks each run's causal trajectory**, so its output is not a valid alternative inference policy and cannot establish that all LiveAct hand artifacts arise the same way.

## What this does and does not establish

Within this fixed velocity trajectory, the *last denoising-step latent correction is sufficient to create the visible hand smear under unchanged prior history*. That is stronger evidence than a correlation between latent MAE and pixel change. It does not prove that earlier velocity corrections or generated-history feedback have no effect; those were already present in the pre-anchor snapshot. It also does not establish that omitting only the final correction improves the full 30-second video's lip sync, identity, or motion timing: the pre-anchor arm here is an offline eight-frame VAE replay and not a fully rerun causal rollout. Thus the inference candidate remains rejected; there is no default behavior change or official PR.

The study is reproducible from three archived snapshots with `python cross_decode_boundary.py --baseline-snapshot ... --velocity-snapshot ... --velocity-pre-anchor ... --baseline-video ... --velocity-video ... --vae checkpoints/LiveAct/Wan2.1_VAE.pth --output-dir ...`. The full LiveAct suite passed **64 tests and 11 subtests** with four upstream Triton deprecation warnings; both archived MP4s decoded to 722 frames and all three snapshots loaded with expected shapes.
