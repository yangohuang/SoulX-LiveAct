# Pre-output latent boundary signal: useful motion proxy, failed artifact trigger

The [prospective design](../superpowers/specs/2026-09-25-pre-output-boundary-signal.md) was fixed before examining these three new signal traces. The question was whether a cheap scalar from the already-computed denoising trajectory could identify *bad* chunk boundaries before VAE decoding. This matters for a selective regeneration policy: an indiscriminate extra DiT pass would be too costly on one RTX 4090, while the earlier [fixed](2026-09-25-seed43-replication.md) and [velocity](2026-09-25-velocity-aware-anchor-ablation.md) anchors failed the motion/lip/hand quality gate.

## Measurement and inputs

Opt-in `--boundary_signal_dir` records block 1–22 without changing model inputs, RNG calls or DiT pass count. At the first and final denoising steps, before optional anchoring, [`boundary_probe.py`](../../boundary_probe.py) computes float32 mean absolute `gap = predicted_first − previous_last`, `previous_speed = previous_last − previous_penultimate`, and `velocity_residual = gap − previous_speed` over channels and space. The last two latents are separated by one latent temporal position (about four output frames), so these are **motion/appearance proxies**, not a direct one-frame seam score. All three 30-second videos are 416×720, 24 FPS, 722 decoded frames and 22 complete eight-transition windows; all use public example image 2, the same 30-second audio trim, prompt `一个人在说话`, three denoising steps, FP8 GEMM/KV, block/cache offload, one resident KV step and one RTX 4090. Only seed and the velocity arm's anchor setting vary.

Full command template: `USE_CHANNELS_LAST_3D=1 CUDA_VISIBLE_DEVICES=0 python generate.py --size '416*720' --ckpt_dir checkpoints/LiveAct --wav2vec_dir checkpoints/chinese-wav2vec2-base --fps 24 --input_json REQUEST.json --fp8_gemm --fp8_kv_cache --offload_cache --block_offload --t5_cpu --disable_compile --fp8_cache_dir /tmp/liveact-fp8-cache --prompt_cache_dir /tmp/liveact-prompt-cache --denoising_steps 3 --resident_kv_steps 1 --seed SEED --motion_anchor_strength STRENGTH --boundary_signal_dir SIGNAL_DIR`; the velocity control adds `--motion_anchor_mode velocity` and strength `0.45`. Spearman values are descriptive for 22 correlated windows, not independent-sample significance tests. The top-5 overlap is with a **pixel-motion** peak, not an artifact label. For seed 42, the five highest gap windows (transitions 372, 532, 148, 660, 244) show speaking, blinks and hand changes in eight-frame review; no conspicuous hand ghosting was evident. Seed 43's high-gap baseline windows (500, 212, 244, 20, 564) likewise largely show normal gesture/expression changes. These observations are limited to short contact windows, not a blind perceptual rating. The signal is therefore correlated with movement but gives no demonstrated artifact specificity.

They contain startup and block progress, but the experiments were not arranged as a controlled latency A/B test.

## Known visual-failure control

The velocity-arm rerun is byte-identical to the previously rejected [velocity video](artifacts/videos/image2-velocity045-seed43-30s.mp4), SHA-256 `f4680d6d493e8a3e4cd82ca3c326152ba151c77add64c66cd7bbb3dc5fe69310`. Its frames 501–507 show conspicuous white/dark hand smearing. The new unanchored seed-43 run has a clear raised-hand gesture at the same nominal window without that smear. The [two-row frame sheet](artifacts/2026-09-25-boundary-signal-clean-vs-velocity-window500.png) shows unanchored on top and velocity on bottom, frames 500–507 left to right.

Thus the visually worse arm has a *smaller* pre-anchor final gap and residual despite a larger immediate pixel change. Across the velocity run, other high-signal windows still include ordinary gestures. A threshold on these scalars would spend extra DiT passes on many legitimate motions and does not distinguish this known artifact from a clear raised-hand event. The failure mechanism is partly expected: the risky change is applied **after** the recorded `x0_pred` and may affect VAE output, so a pre-anchor magnitude cannot certify the post-intervention appearance. This is a causal interpretation of the code path and observed traces, not a proven model-wide explanation.

## Reproducibility, cost and decision

Both unanchored diagnostic MP4s differ in hash from the earlier uninstrumented baseline videos (`4fc7fa...` versus `a3af88...` for seed 42; `aee2cd...` versus `74764f...` for seed 43). The seed-42 grayscale average absolute difference is about 0.95/255; seed 43 about 4.56/255. Their same-video motion windows were recomputed from each new MP4; **no cross-run pixel alignment is assumed**. The velocity rerun is byte-identical, which confirms the known failure control. During seed-42 capture only, timestep metadata used `timestep.item()`; later runs used the equivalent CPU schedule value to avoid an extra synchronization. No sampling or metric equation changed, but end-to-end runtime comparisons across these runs are not controlled.

The scalar helper's standalone warm-GPU benchmark was 0.051 ms/call for 100 calls on the 4090, using BF16 tensors shaped `[16,8,90,52]`, followed by a GPU synchronize. Two calls per later block add about 44 helper invocations for a 30-second clip and no extra DiT pass. This isolated figure does **not** include model, VAE, JSON transfer, or scheduling effects; it does not imply real-time generation. The full LiveAct test suite passed 60 tests, 11 subtests with four upstream deprecation warnings. Source SHA-256 after the metadata-refactor is `c89cfdd558c3a098c722dc4d0cc3a14697af42ee53f7a1c791438ca9a9128fc0` for `generate.py`, `7d223b3b7918ec1eea08993285f22379305787a13f6cbdc7151cc72ca06aa00c` for `boundary_probe.py`, and `34ed797eca62a968b02c5d9e34bed71a2b09622550bf5a1f275f64669a7896e0` for the analyzer.

**Decision: reject these three latent-MAE scalars as a trigger for selective fallback.** Keep the opt-in probe as a low-cost research instrument; do not add regeneration or default inference changes. The next more informative study should isolate *where* a failure is created (denoising correction versus VAE/context decoding versus autoregressive history) using synchronized latent/decoded probes on an already observed bad window, then test any new risk score against visually labeled normal gestures and artifacts. One identity, two seeds and one induced failure cannot establish long-form robustness, and no official SoulX PR is warranted by this negative quality result alone.
